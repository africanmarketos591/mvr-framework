# Independent receiver qualification

Run node conformance/receiver-kit/independent/run.mjs result.json with Node 24, Python 3.11 or newer and OpenSSL 3. The published GitHub Actions workflow executes on a fresh Ubuntu host without an AMOS account key. A buyer can run the same command in its own environment.

The synthetic issuer uses the standard lab client. A separate Python process verifies the session registry against the repository-pinned lab root and verifies receipts, effect digests, feed signatures, sequence links, elapsed time and revocation. Only a zero-value draft in the lab system can be recorded. SQLite serializes writes and enforces commit ID uniqueness. The verifier checks the current signed feed before acting. This test fixture uses bounded lab sessions and replays the complete feed from genesis.

The unchanged HTTP receiver suite checks 14 delivery cases. The additional checks restart the receiver and submit a previously signed, still-unexpired commit after revocation. The latter passes only if the receiver refuses it based on fresh state and the database gains zero drafts. A separate observer opens the ledger in read-only mode before and after delivery. It counts the positive-control row, the revoked commit ID and all drafts directly in SQLite. The workflow logs record the source commit, release manifest, assertions and outcomes. GitHub operates the runner; the repository owner controls the workflow. Buyer ownership is a separate fact.
