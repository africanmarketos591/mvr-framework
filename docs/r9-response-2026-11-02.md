## What we measured that went against us

- **First passes are kept as measured.**
  - Set A: 229 of 240, with 8 false favorable.
  - Set B: 64 of 80, with 16 false favorable (`live-effect-set-b-first-pass.json`).
  - Audit cohort: 14 of 16.
- **`.1` was superseded** because the licensed favourable-path regression found a permission statement no longer validating against the closed published schema. `effect_state` gained `canonical_action_id` and `modelled_as`.
- **`.2` was superseded** because our own sweep of the authority modules for raw spelling comparisons found four places where an alias and its canonical identifier still answered differently: delegation scope, designation coverage, the permission position, and review models that could name one action twice. Each failed closed, and each changed the answer by spelling. The `.2` R9 run also had one full-advisory REST/MCP parity miss in set A (55 of 56); R8's regression showed one such miss once before.
  - **It did not reproduce:** 144 of 144 pairs in an isolated live rerun on `.2`, and 864 of 864 REST-against-MCP and REST-against-REST pairs in-process.
  - **Worker analytics for the miss window show no worker error:** no exception and no CPU or resource limit. The only non-success outcomes were client disconnects, which also appear in clean runs.
  - **Conclusion:** the miss is consistent with a reply that never reached the runner intact, which the runner then scored as a difference. It cannot be tied to one request, because the first runner did not record it.
  - **Runner change:** both live runners now retry an unreadable, throttled or gateway reply with a logged retry, and record any parity miss with both statuses and the first differing field. The published report must show zero misses.
- **First `.3` live run:** it lost suites to an AMOS runner defect (a variable that shadowed the request body) and then to a network outage on the operator machine. Both are described in the run notes of the evidence README; the published reports come from the rerun.
- **Budget raised:** the licensed MCP tool-list byte budget in five private tests rose from 215,000 to 230,000, because the exact-effect and submission tools now publish detailed output schemas.

## Compatibility

- Effect decisions change where support stated a missing link or a qualifier, where a qualifier stood beside direct support, and for internal planning under adverse records. Normative digests include `canonical_action_id`.
- `effect_state` in permission statements may carry `canonical_action_id` and `modelled_as` (optional, so earlier statements still validate).
- Dispositions require `reviewer`, and the response carries `disposition_receipt`.
- `schedule_meeting` resolves to `external_meeting`; the internal alias is `schedule_internal_meeting`.
- A review model that names an alias and its canonical identifier is refused with `REVIEW_TOOLS_EFFECT_ACTION_DUPLICATE`.
