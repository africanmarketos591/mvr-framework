## One clean case we did not force

On `/v1/claim-audit`, `status` reports reviewer verification. A cited claim without a stored accountable review is `cited_unverified`, and the route says `weak_support_detected`, while the audit finds no defect and the controlling decision is `clear`. Our own R16 runner counts that as disagreement, so `h2-clean` and `k2-clean` are listed as misses. We kept the verification rule rather than weaken it to pass the row.

## What changes for integrators

- The internal recommendation can now be `conditional` where it used to be `insufficient`.
- Release and board fields can change to `hold_for_review` when an audit finding controls. A red-team or release route with a high native strict blocker says `hold`.
- A licensed REST first call returns `rest_next_call`. Send it as written.
- `rotateRegistry` in the receiver kit returns `{state: 'applied' | 'deferred_until_activation', ...}`. Wait for `retry_after_ms` when it defers.
- The native claim audit now reads links written inside a claim, so such claims move from `unsupported` to `cited_unverified`.

- The deferred key succession was exercised in unit tests, not in a live run.
- We did not observe a transient server failure, and we did not induce one.
