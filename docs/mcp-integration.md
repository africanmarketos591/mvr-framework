# African Market OS-MVR API: public and licensed MCP integration

Contract update: 2026-09-07. Public endpoints are evaluation-only, not production scoring or authorization.

Compatibility notice for 2026-09-07.engine-contract.8: complete source-to-target claim linkage is required for content-bearing or load-bearing evidence, including every item in a partially linked pack. Refresh licensed tools/list; follow only returned call_now handoffs. Licensed evidence_fit now blocks declared load-bearing country/date conflicts. Excluded rows that also supply scoring values remain non-decisive even if called background. decision-check rejects output receipt fields submitted as request authority with OUTPUT_RECEIPT_NOT_REQUEST_AUTHORITY; it is not an input receipt-verification endpoint. See the migration and interpretation sections below before upgrading an integration.

## Connect and parse

GET /mcp/preflight returns discovery for five tools. GET /mcp/guided returns the one-call alternative. Neither requires a key. Adding a paid key here does not upgrade this public transport.

Use tools/list on the endpoint you actually call for its live inputSchema and, when supplied, outputSchema. Tool outputSchema validates result.structuredContent, not the JSON-RPC envelope. On /mcp/preflight and /mcp/guided, result.content is a compact human-readable summary for compatible clients, not a second schema or a complete JSON copy. Other connector profiles may retain full serialized content for compatibility. Render the message for people and use structuredContent for branching. Never interpret isError=false as evidence completeness or approval.

Legacy clients can initialize with 2025-11-25 or 2025-06-18. Modern 2026-07-28 is stateless and uses server/discover instead of initialize. Every modern request needs matching HTTP and params._meta values. Top-level _meta and mcp_protocol_version are NOT modern metadata. Omitting modern headers can select legacy compatibility; that is not modern conformance.

Modern tools/list example (POST /mcp/preflight):

Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/list

{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientInfo":{"name":"your-client","version":"1"},"io.modelcontextprotocol/clientCapabilities":{}}}}

For tools/call use Mcp-Method: tools/call and Mcp-Name matching params.name. Keep _meta inside params beside name and arguments, not inside arguments. Preserve the server's mcp_next_call as the next params.name and params.arguments; add protocol metadata beside them. Follow only continuation_disposition=call_now. At await_input ask the user; at terminal stop. Handle HTTP 400 protocol errors, 429 Retry-After and temporary 503 without tight retry loops.

## Collect public evidence without guessing fields

The public shared item schema is https://africanmarketos.com/schemas/mvr-public-preflight-evidence.schema.json and is inlined in public tools/list. Public first call and guided input use root fields; later canonical tools use arguments.payload. stage is free text. evidence_available contains optional labels, not proof. Accepted string labels are retained in executable handoffs; evidence_received shows only a labelled bounded preview. For document summaries, supply incomplete evidence_pack items so missing provenance can be addressed. Supply one complete evidence_pack (or the evidence_items alias), not conflicting copies.

An incomplete illustrative item, intentionally NOT verified:

{"id":"example-1","claim":"A redacted claim awaiting review","evidence_type":"interview_summary","source_class":"structured_field_research","stakeholder_class":"customer","verification_status":"self_attested","source_doc_id":"your-private-record-reference","source_date":"2026-09-01","geography":"target market","load_bearing":true}

Replace illustrative values with consented real metadata. Do not send personal identifiers, credentials, private interview transcripts or confidential documents. Source URLs are references; the public tool does not fetch them. verification_status is a caller declaration, not AMOS verification. An authentic document does not verify every claim attributed to it; an arithmetic check does not authenticate underlying transactions. Renaming copied evidence or inventing identifiers does not make it independent.

evidence_input_feedback gives indexed paths and machine codes, with at most 40 issue messages. Correct type errors before retrying; warnings identify missing metadata, not automatic rejection of genuine evidence. The evidence container and verified boolean are not accepted substitutes for evidence_pack and verification_status. Use source_date, not date; use source_doc_id or provenance_ledger, not an unstructured provenance field. Do not invent references or declare verification just to pass. source_locator identifies a particular document, not a shared storage folder. The public gate checks structural coverage, declared source overlap and unverified load-bearing items. Passing it only completes public routing. source_review remains outstanding even when evidence_collection_plan.tasks is empty: original authenticity, claim support, contradictions, permission scope and the human disposition have not been assessed.

evidence_fit reports comparisons of declared country and date metadata, not source authentication. Use country codes or recognized names for the target, and evidence_geography.country for a source country when geography describes a wider area. Accents and curly apostrophes in recognized country names are normalized; ambiguous localities are not guessed. Known foreign-country items and items beyond context_freshness_window_days are excluded from coverage. They may remain background when the decision does not depend on them; either load-bearing flag set to true makes that conflict blocking. Do not change source facts or dependency flags merely to pass. Contradictory metadata, invalid dates, future sources relative to analysis, and invalid policies must be corrected.

analysis_date accepts YYYY-MM-DD or an ISO timestamp with timezone, no later than today in analysis_timezone (optional valid IANA name, UTC by default). The server does not infer timezone from country or IP. Date-only inputs keep the specified calendar day; timestamp inputs are compared in that same timezone. This handles a local day ahead of UTC without accepting genuinely future dates. Source dates use the same formats. context_freshness_window_days is an optional positive integer chosen for the decision, not a scientifically calibrated default. Without it, source age is reported and freshness remains unassessed. Missing dates and unrecognized broad regions remain unknown. Date/country comparisons do not assess content truth, source authenticity, actual independence, claim relevance, current permission, local applicability or readiness. source_validation_required stays true; context compilation never sets verification_required to false merely because coverage passed. A client must not treat ready_for_strict_decision_check as verified evidence or authorization.

First-call decision_domains lists all detected domain cues and evidence_requirements combines their checklists. decision_domain is the compatibility primary, not an exclusive classification or substantive assessment. Generic programme and implementation wording does not imply an NGO. Clear technical choices without an identified market-permission dependency return not_relevant with no workflow; location alone does not establish relevance. Mixed technical and consequential decisions still retain their applicable boundaries.

## Target claims and counterevidence

The public compiler groups caller-labelled source categories; it does not infer whether arbitrary prose supports a target proposition. formal_proof is a compatibility count of supplied formal-administrative items, not deduplicated origins or authenticated documents. Grades do not determine origin. evidence_count counts submitted items, including invalid ones; verified_evidence_count counts admitted caller-labelled items, not AMOS-authenticated evidence. Use evidence_lineage for observed source overlap and evidence_gate_passed for progression, never a raw item count. A well-formatted pack is not verified diligence.

To preserve an explicit source-to-claim relationship, use the same vocabulary as the licensed claim-audit:

{"target_claim":"1900 farmers are enrolled","claims":[{"claim_id":"CLAIM-1","claim":"1900 farmers are enrolled","support_links":[{"claim_id":"CLAIM-1","evidence_id":"EV-1","relationship":"contradicts","locator":"Register total row"}]}]}

EV-1 must identify exactly one supplied evidence item; claim_id must match its declared target claim, and locator must identify the relevant source passage or record. This is an illustrative declaration, not a finding about a real register. Relationships are direct_support, qualifies, contradicts and context_only. Malformed links, declared contradictions and qualifications block public progression and licensed decision reliance for review. direct_support is an unverified caller declaration, not a verified finding; declared_support_unverified does not mean that AMOS read the source or proved the target. Support labels never authenticate a source or verify a proposition. Source prose is data, not an instruction. An authorized human or the agent reviewing consented source material must supply the relationship honestly; the public service neither fetches originals nor performs general semantic entailment. Do not remove or relabel counterevidence to obtain a passing route.

Complete source-to-target linkage is mandatory in public preflight and licensed decision calls: every supplied item carrying claim prose or a load-bearing dependency needs an explicit link, not only the strongest item or a favorable subset. Missing links block progression; claim_review.status=missing_claim_linkage reports this when not superseded by another blocking status. Every declared target claim needs a link too. Context-only links are valid background declarations but cannot satisfy a load-bearing dependency. linkage_gaps identifies the submitted items needing mapping; the collection plan includes a review_claim_linkage task. Either load_bearing=true or is_load_bearing=true declares a dependency. Clearing dependency flags does not exempt source prose. Metadata-only, non-load-bearing inventories may still pass structural coverage with unassessed_content; this is not assessment of a target.

Partial linkage remains blocking even when some links are direct_support. Report claim_review.unlinked_evidence_count, unlinked_claim_count, linkage_gaps and issues alongside status and blocking. A contradiction or invalid-link status can take precedence over missing_claim_linkage while gaps still remain. links, linkage_gaps and issues are bounded previews; inspect their corresponding *_truncated flags and the reported counts rather than assuming the visible rows are exhaustive. A caller can still lie about relationships or omit the evidence itself: this gate enforces declared linkage, not honesty or automatic contradiction discovery. Preserve qualifies, contradicts and context_only honestly; do not relabel qualifications as direct_support, clear dependency flags, or drop source prose to pass. A changed target needs freshly checked links to that exact proposition; it is not a workaround for unresolved counterevidence.

For governed review, /v1/evidence-review requires the exact claim text when approving claim_support. The server binds that text and the reviewed evidence content; /v1/claim-audit checks the persisted event in the authorized tenant/workspace. ID-only historical events cannot verify a proposition and require fresh authorized review. Buying Starter or choosing strict_calibrated does not itself grant reviewer roles, all utility routes or document authentication. Access follows the current plan and credential scope.

Public tools/list output schemas advertise decision_domains, domain_routing_basis, evidence_requirements, evidence_input_feedback, evidence_fit, source_review and claim_review. Optional output fields are not required on every terminal or error state. Inputs intentionally permit incomplete context so the service can ask for corrections. Impossible, conflicting and future-relative source dates are excluded from coverage and reported at first call through indexed feedback as well as evidence_fit.

An explicitly internal purchase declaring no new market, no new counterparty and no permission question can terminate as not_relevant. An equipment purchase or internal-only/own-use purchase without sufficient scope returns awaiting_scope_clarification, await_input and no workflow. Ask the scope question before collecting expansion evidence. Additional borrowing, credit, regulatory, supplier, contract, expansion or other consequential cues retain preflight routing. This deterministic router is not general natural-language negation understanding. not_relevant is a relevance disposition, not financial or purchase approval.

## Public intake and licensed evidence contracts

The public MCP item schema is intentionally intake-friendly; it is not the licensed REST EvidenceItem schema. REST clients should read https://africanmarketos.com/api/openapi.agent.json (components.schemas.EvidenceItem and each route's request schema) and https://africanmarketos.com/v1/schema (evidence_item_enums, public_metrics_schema, public_metric_registries). These publish source_class, evidence_type, collection_method and metric vocabularies. Follow the actual route types, required fields, enums and references; an open additionalProperties object permits extra metadata but does not make it evidence of support. Do not impose an object-only restriction where the served schema permits a string. A 422 is a correction request, not evidence rejection on its merits. Do not turn a founder assertion into independently verified field research to satisfy an enum. Preserve entity_reported origin, the actual collection method and missing provenance. Counts and metrics belong in the fields and units specified by the route, not arbitrary structured_values keys. imputed_share is not a lie detector. Declare dates, geography and any decision-specific freshness window in their structured fields; prose alone does not enable those comparisons.

## Licensed migration and handoffs

Read-only input discovery is available at /v1/evidence-guide and /v1/recommended-inputs, subject to the credential's route scope. Completeness exposes field_sample_report.issues with stakeholder_class, required and observed weighted samples; the full checks remain under metrics.field_research.sample_sufficiency. HTTP 200 means the request was processed, not that evidence passed: inspect status, blockers, claim_review, evidence_fit and continuation_disposition. REST /v1/first-call is keyless public activation by design, even with a credential header; use /mcp/runtime for the licensed five-tool transport. Authenticated downstream REST results identify their execution environment, not authority to act. Timezone-less datetime strings need their known offset before a date-fit decision; a genuine YYYY-MM-DD calendar date remains supported. Never guess an offset merely to pass.

Use https://africanmarketos.com/mcp/runtime for licensed MCP, with credentials configured securely in the host, never in tool arguments or reports. It exposes the same five canonical tool names as public preflight, but calls governed REST handlers under the caller's plan, tenant/workspace, response profile and output controls. It is not an upgrade obtained by adding a paid key to /mcp/preflight, and access alone is not a verdict or an authorization.

Refresh tools/list on /mcp/runtime when migrating; do not cache public descriptors under the same tool names. Licensed input schemas inline the typed REST EvidenceItem and route components, including rich structured values, provenance and sample metadata. mvr_first_call takes fields directly in arguments; the later four tools take arguments.payload. The incomplete public example above is not a complete licensed EvidenceItem template. Use the actual licensed schemas and REST component definitions to construct a valid pack while preserving the real source origin and missing information. Licensed descriptors intentionally do not reuse the public non-scoring outputSchema; if outputSchema is absent, do not validate a licensed scored result against a public routing schema or infer that no scoring occurred.

Follow the returned native MCP handoff exactly while continuation_disposition=call_now: pass mcp_next_call.name and mcp_next_call.arguments unchanged as the next tools/call params.name and params.arguments, adding only required protocol metadata beside them. At await_input, stop automatic chaining and ask for the specified missing or corrected input. At terminal, stop. If the disposition or mcp_next_call is missing or inconsistent, do not reconstruct a next call from prose, an example, or a guessed stage. This rule depends on the fields actually returned by the connected deployment; do not assume an older deployment already emits native licensed handoffs.

An unresolved or ambiguous identity does not itself require a REST switch. With declared scope and evidence, entity-resolve can emit a native mvr_evidence_completeness call while resolved remains false. Without evidence, await_input and null mcp_next_call are intentional. continuation_resume names the same MCP tool to call only after the user supplies the missing or corrected inputs; retain the previous payload and do not retry it unchanged. A known company name is not a substitute for case evidence. recommended-inputs accepts sector as optional descriptive context, but still requires a supported entity_archetype or category; it never guesses one from sector alone.

Do not invent an entity, canonical archetype, country, date, target claim, source reference or any other missing field to keep the chain moving. Preserve the original sector wording, exact target and declared relationships, and use a returned resolved archetype only as provided. Workflow IDs track operational continuation, not authority. A handoff permits the next API call, not the proposed market action. Do not apply the public retry window or public sandbox output assumptions to licensed calls; follow the returned instructions and current licensed contract.

## Interpret licensed results

strict_calibrated means stricter calibration-asset admission and no heuristic substitution, not a promise of lower confidence or more reason codes than full_advisory on every case. Advisory fallback paths can add a confidence cap which is absent when strict asset requirements are met. Compare authorization, evidence gates, calibration basis and confidence_ceiling_applied on matched inputs. decision_interpretation.profile_contract states that distinction; floor_verdict_reconciliation binds the displayed lower bounds to this response's actual candidate verdict, dominant failure, ceiling reason and output-use blockers. It does not recompute a verdict from executive numbers or grant execution permission.

REST first-call is not a credential test: response_meta.credential_validation_performed=false and transport=public_rest_activation explain public_activation even when a key was sent. Licensed MCP first-call reports credential_validation_performed=true and transport=licensed_mcp after its actual authentication checks. The environment describes the request being executed, not the user's subscription or all later routes.

Receipt inputs on decision-check return OUTPUT_RECEIPT_NOT_REQUEST_AUTHORITY with indexed details and receipt_validation.performed=false. Receipt validity, expiry and revocation remain unknown, equally for genuine, old and fabricated output fields. This is an input-contract rejection, not replay detection or stored-receipt verification. Remove output-only fields for a fresh evidence assessment. Stored-record checks require the separately authorized workflow; an evaluation key does not gain access from supplying a receipt.

Licensed results expose decision_interpretation for the scale, permission meaning, threshold limits and authority precedence. claim_review.claim_subjects identifies which claim IDs and item IDs have only declared support; it does not publish source contents. linkage_status distinguishes missing from partial mapping. evidence_fit is shared with public date/country policy, with licensed object-geography compatibility. Excluded scoring rows cannot yield a current candidate verdict: retained integers are diagnostic, not admitted current evidence. Correct the source/decision mismatch honestly, or supply genuinely decision-relevant evidence. A configured freshness window is your declared policy, not proof of current validity.

Native licensed handoffs return the caller's supplied evidence to the same authorized MCP host with canonical context, not a new audience. Never forward the whole handoff as a public report. They do not transmit credentials in arguments, retrieve extra private records or execute another tool. The host still decides whether to call; each call rechecks credential scope. REST continuation pointers remain available for REST clients.

1. Read claim_review.blocking, abstention_reason_codes, why_no_verdict and decision_authorization before presenting a recommendation. A blocking claim review or abstained status overrides any numeric candidate signal. Preserve all stated abstention reasons, not just the claim-review reason. Missing authorization fields are not permission.
2. When present, normalized scores.executive and scores.dimensions are 0-100 MVR score readouts, not 0-1 probabilities. For example, scores.executive.permission=57 means 57 score points, not a 57% probability of success or a licence-validity percentage. Executive values aggregate dimension evidence and need not equal the same-named dimension. Null or omitted values are unavailable, not zero. Do not multiply these scores by 100 or mix them with the separately scoped confidence fields.
3. permission is a modeled relational operating dimension, not confirmation that a statutory licence is valid or that a regulator authorized the proposed activity. Applicable numeric thresholds and sample gates are necessary where required, not sufficient for readiness or use of the output. Claim linkage, source review, geography, freshness, provenance, calibration, vetoes and other reported gates still constrain interpretation. Do not reconstruct a verdict from a mean score or hard-code one universal threshold across archetypes and profiles.
4. Respect diagnostic_only=true, not_a_verdict=true and decision_use=non_decisive_diagnostic_only wherever returned. Retained scores, intervals, per-class sample issues, sample_gate_passed and finite_population_review are diagnostic disclosures on a blocked result, not approval. Preserve calibration_basis and calibration/proxy limitations with the readout; a calibration disclosure or census declaration does not waive a gate. Blocked results may intentionally omit old board, reconciled, counterfactual and advisory branches. Never fill those omissions from an earlier response or promote a diagnostic branch to the headline.
5. Treat pilot_only as a candidate ceiling, not execution permission or a complete pilot plan. Neither pilot_ready nor ready_to_scale by itself authorizes action. Read decision_authorization.status, authorized_use, not_authorized_use, blocking_gates and human_review_required together with decision_reliability.not_authorized_for and any execution_authorization_state. Even authorized is bounded permission to use the API output for the listed purpose, not an autonomous launch, credit, investment, legal, regulatory, board or scale approval. A human-approved pilot still needs its actual scope, safeguards, owners and review conditions; do not invent them from the label.

Compact output is a projection, not a weaker safety contract: preserve its answer, authorization boundaries, claim review, abstention reasons and diagnostic/calibration disclosures. Do not interpret omitted bulky branches as passed checks. Neither a receipt/hash, deterministic replay, direct_support label, successful tool call nor strict_calibrated profile proves source truth, detects all fraud, or establishes empirical superiority over another method. Empirical performance claims need separately scoped evaluation evidence; this integration contract makes no such guarantee.

## Resume a corrected public pack

At an evidence pause, mcp_next_call is deliberately null. evidence_collection_plan lists missing-proof tasks, not external actions already performed. evidence_recovery is guidance requiring new input and user authorization, NOT a next call to execute unchanged. The free Evidence Builder at https://africanmarketos.com/mvr-evidence-builder/ can help the user prepare sources; it is optional.

The client retains the consented original context and entire pack. With corrected evidence for the same decision inside the original two-hour window, call mvr_evidence_completeness again with arguments.payload containing that full context, complete replacement pack, workflow_id and workflow_expires_at. No raw evidence is stored for retrieval or appended server-side. The ID is operational measurement, not authentication or an entitlement. After expiry, a changed decision or lost context, start mvr_first_call afresh. Each guided retry starts a fresh bounded sequence with its complete corrected input.

No Notion, Airtable or Jira connector is required. A client may show the structured task list to its user and, only after separate approval, copy a minimized version into their task system. AMOS does not do that automatically. Completion, a lead, checkout and payment remain different events. Optional paid routes never authorize purchase or replace evidence collection.

## Reproducible reports

Report endpoint, protocol version, UTC time, HTTP status, cf-ray, error code and a redacted minimal request. Do not share credentials or private evidence. A transient GET failure needs those identifiers to investigate; a current successful GET cannot disprove a past outage.

For host/model comparisons, isolate the intended connection and inspect the actual selected server and tool in the trace. Configuring a direct MCP URL does not prove the host used it if another connector exposes equivalent tools. Record both configured model IDs and any available backend snapshot, prompts, additional host policy, caching, repeated-run counts and full request/response traces. Include a policy-only control when testing whether AMOS adds value beyond instructions. Same-vendor model swaps are not cross-vendor validation; synthetic cases are not customer outcomes. Separate timing, total tokens, uncached tokens and actual price rather than interpreting token ratios as a bill.
